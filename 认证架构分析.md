## 一、基础知识铺垫

### 1.1 什么是单点登录 (SSO)

**单点登录 (Single Sign-On, SSO)** 是一种身份认证机制，允许用户使用一组凭证（如用户名和密码）登录一次后，即可访问多个相互信任的应用系统，无需重复登录。

```
┌─────────────────────────────────────────────────────────────┐
│                        SSO 认证中心                          │
│                    (CAS Server / Keycloak)                  │
└─────────────────────────────────────────────────────────────┘
         ▲              ▲              ▲
         │              │              │
    ┌────┴────┐    ┌────┴────┐    ┌────┴────┐
    │  App A  │    │  App B  │    │  App C  │
    │ (Client)│    │ (Client)│    │ (Client)│
    └─────────┘    └─────────┘    └─────────┘
         ▲              ▲              ▲
         │              │              │
         └──────────────┼──────────────┘
                        │
                   ┌────┴────┐
                   │   用户   │
                   │ 登录一次 │
                   └─────────┘
```

**SSO 的核心价值**：
- **用户体验**：一次登录，处处访问
- **安全集中管理**：统一的认证策略、密码策略、审计日志
- **降低运维成本**：减少密码遗忘、账号管理的工作量

### 1.2 CAS 协议详解

**CAS (Central Authentication Service)** 是耶鲁大学发起的开源企业级单点登录解决方案，使用基于票据 (Ticket) 的认证机制。

#### CAS 核心概念

| 术语 | 全称 | 说明 |
|------|------|------|
| **TGT** | Ticket Granting Ticket | 票据授权票据，存储在 CAS 服务器，代表用户的 SSO 会话 |
| **TGC** | Ticket Granting Cookie | 存储在浏览器的 Cookie，包含 TGT 的引用 |
| **ST** | Service Ticket | 服务票据，一次性使用，用于向具体应用证明身份 |
| **Service** | - | 请求认证的客户端应用地址 |

#### CAS 2.0 协议流程

```
┌──────────┐         ┌──────────┐         ┌──────────┐
│  Browser │         │  Client  │         │CAS Server│
│  (用户)   │         │ (应用端) │         │ (认证端) │
└────┬─────┘         └────┬─────┘         └────┬─────┘
     │                    │                    │
     │ 1. 访问受保护资源    │                    │
     │───────────────────▶│                    │
     │                    │                    │
     │ 2. 302 重定向到 CAS │                    │
     │◀───────────────────│                    │
     │                    │                    │
     │ 3. 请求 CAS 登录页  │                    │
     │────────────────────────────────────────▶│
     │                    │                    │
     │ 4. 返回登录表单     │                    │
     │◀────────────────────────────────────────│
     │                    │                    │
     │ 5. 提交用户名/密码  │                    │
     │────────────────────────────────────────▶│
     │                    │         6. 验证凭证 │
     │                    │         生成 TGT/TGC│
     │                    │         生成 ST     │
     │                    │                    │
     │ 7. 302 + ST + Set-Cookie(TGC)          │
     │◀────────────────────────────────────────│
     │                    │                    │
     │ 8. 携带 ST 回到应用 │                    │
     │───────────────────▶│                    │
     │                    │                    │
     │                    │ 9. 后端验证 ST      │
     │                    │───────────────────▶│
     │                    │                    │
     │                    │ 10. 返回用户信息    │
     │                    │◀───────────────────│
     │                    │                    │
     │ 11. 登录成功，设置会话│                   │
     │◀───────────────────│                    │
     │                    │                    │
```

### 1.3 OIDC / OAuth 2.0 协议详解

**OAuth 2.0** 是一个授权框架，**OIDC (OpenID Connect)** 是构建在 OAuth 2.0 之上的身份认证层。

#### OAuth 2.0 vs OIDC

| 特性 | OAuth 2.0 | OIDC |
|------|-----------|------|
| **目的** | 授权 (Authorization) | 认证 (Authentication) |
| **核心问题** | "这个应用能代表我做什么？" | "这个用户是谁？" |
| **返回内容** | Access Token | Access Token + **ID Token** |
| **用户信息** | 需要额外请求 UserInfo | ID Token 自带用户信息 |

#### OIDC 核心概念

| 术语 | 说明 |
|------|------|
| **Authorization Code** | 授权码，一次性使用，用于交换 Token |
| **Access Token** | 访问令牌，用于访问受保护资源 |
| **ID Token** | 身份令牌 (JWT)，包含用户身份信息 |
| **Refresh Token** | 刷新令牌，用于获取新的 Access Token |
| **UserInfo Endpoint** | 用户信息端点，返回用户详细信息 |

#### OIDC 授权码流程 (Authorization Code Flow)

```
┌──────────┐         ┌──────────┐         ┌──────────┐
│  Browser │         │  Client  │         │   OIDC   │
│  (用户)   │         │ (应用端) │         │ Provider │
└────┬─────┘         └────┬─────┘         │(Keycloak)│
     │                    │               └────┬─────┘
     │ 1. 点击"登录"       │                    │
     │───────────────────▶│                    │
     │                    │                    │
     │ 2. 302 重定向到授权端点                  │
     │    (client_id, redirect_uri, scope,     │
     │     response_type=code, state)          │
     │◀───────────────────│                    │
     │                    │                    │
     │ 3. 请求授权页面     │                    │
     │────────────────────────────────────────▶│
     │                    │                    │
     │ 4. 登录 + 授权同意  │                    │
     │────────────────────────────────────────▶│
     │                    │                    │
     │ 5. 302 + code + state                  │
     │◀────────────────────────────────────────│
     │                    │                    │
     │ 6. 携带 code 回到应用│                   │
     │───────────────────▶│                    │
     │                    │                    │
     │                    │ 7. 用 code 交换 token│
     │                    │ (POST /token)       │
     │                    │───────────────────▶│
     │                    │                    │
     │                    │ 8. 返回 tokens      │
     │                    │ (access_token,      │
     │                    │  id_token,          │
     │                    │  refresh_token)     │
     │                    │◀───────────────────│
     │                    │                    │
     │                    │ 9. 请求用户信息(可选)│
     │                    │ (GET /userinfo)     │
     │                    │───────────────────▶│
     │                    │                    │
     │                    │ 10. 返回用户信息    │
     │                    │◀───────────────────│
     │                    │                    │
     │ 11. 登录成功，设置会话│                   │
     │◀───────────────────│                    │
```

### 1.4 CAS vs OIDC 对比

| 维度 | CAS | OIDC |
|------|-----|------|
| **协议标准** | 专有协议 | 开放标准 (建立在 OAuth 2.0 上) |
| **认证方式** | 基于票据 (Ticket) | 基于令牌 (Token/JWT) |
| **单点登出** | 原生支持 (Back Channel) | 需要额外配置 |
| **跨域支持** | 需要代理或 CORS | 原生支持 |
| **移动端支持** | 较弱 | 优秀 (天然支持 Bearer Token) |
| **社交登录** | 需要插件 | 原生支持 |
| **复杂度** | 相对简单 | 功能丰富但复杂 |
| **典型实现** | Apereo CAS | Keycloak, Auth0, Okta |

### 2.2 核心设计理念

**1. 无状态设计 (Stateless)**
```java
// WebSecurityConfig.java
http.sessionManagement()
    .sessionCreationPolicy(SessionCreationPolicy.STATELESS);
```
- 禁用 Session，使用 Redis 存储 Token
- 支持水平扩展和分布式部署

**2. 统一 Token 机制**

无论用户通过哪种方式登录（表单/CAS/OIDC），最终都生成统一格式的 Token 存入 Redis：
```
Redis Key: auth:token:access:{token}
Redis Value: CustomUserDetails 对象
```

**3. 条件化配置**

通过 `@ConditionalOnProperty` 按需启用 SSO：
```java
@ConditionalOnProperty(prefix = "sso.cas", name = "enabled", havingValue = "true")
public class CasSecurityConfig { ... }

@ConditionalOnProperty(prefix = "sso.keycloak", name = "enabled", havingValue = "true")
public class KeycloakSecurityConfig { ... }
```

### 2.4 统一 SSO 架构设计（新增）

本项目采用 **前端驱动的 SSO 流程**，通过统一的 API 层封装不同的 SSO 协议：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                              前端 (Vue 3)                                   │
│                                                                             │
│  登录页点击 SSO 按钮                                                         │
│       │                                                                     │
│       ▼                                                                     │
│  GET /api/auth/sso/{provider}/login-url  ──────▶  获取 SSO 登录 URL         │
│       │                                                                     │
│       ▼                                                                     │
│  window.location.href = loginUrl  ──────────────▶  跳转到 SSO 服务器         │
│       │                                                                     │
│       ▼                                                                     │
│  SSO 回调 /api/auth/sso/{provider}/callback?ticket=xxx                      │
│       │                                                                     │
│       ▼                                                                     │
│  重定向到前端 /dashboard?token=xxx  ◀────────────  后端验证并生成 Token      │
│       │                                                                     │
│       ▼                                                                     │
│  路由守卫检测 URL 中的 token，保存到 localStorage/Cookie                      │
└─────────────────────────────────────────────────────────────────────────────┘
```

**核心优势**：
- **前端不暴露 SSO 端点**：登录 URL 由后端统一生成
- **统一的回调路径**：所有 SSO 提供商使用 `/api/auth/sso/{provider}/callback`
- **策略模式**：通过 `SsoProvider` 接口抽象不同协议，易于扩展新的 SSO 方式
- **解耦前后端**：前端只需调用统一的 API，无需了解具体 SSO 协议

## 三、CAS 认证流程深度解析

### 3.1 三端交互视角（前端驱动模式）

#### 客户端 (Browser/Frontend)

```
1. 用户访问: http://localhost:3000/dashboard
   ↓
2. 前端检测未登录，显示登录页，点击"CAS 登录"按钮
   ↓
3. 前端调用 API: GET /api/auth/sso/cas/login-url?redirectUri=http://localhost:3000/dashboard
   ↓
4. 后端返回: { loginUrl: "https://cas.example.com/cas/login?service=...", state: "xxx" }
   ↓
5. 前端跳转到 loginUrl
   ↓
6. 用户在 CAS 页面输入用户名密码
   ↓
7. CAS 登录成功，重定向回:
   http://localhost:8888/api/auth/sso/cas/callback?ticket=ST-xxx&redirectUri=...
   ↓
8. 后端验证 ticket，生成 token，重定向到前端:
   http://localhost:3000/dashboard?token=xxx
   ↓
9. 前端路由守卫检测 URL 中的 token，保存到 localStorage/Cookie
   ↓
10. 前端清理 URL 参数，进入 dashboard 页面
```

#### 认证端 (CAS Server)

CAS Server 的核心职责：
1. **呈现登录界面**：`/cas/login`
2. **验证用户凭证**：检查用户名密码
3. **管理 SSO 会话**：生成 TGT，设置 TGC Cookie
4. **签发服务票据**：生成一次性 ST
5. **验证服务票据**：`/cas/serviceValidate`

```
CAS Server 端点:
├── GET  /cas/login?service={url}     # 登录页面
├── POST /cas/login                   # 处理登录表单
├── GET  /cas/serviceValidate         # 验证 ST (CAS 2.0)
│         ?ticket={ST}&service={url}
├── GET  /cas/p3/serviceValidate      # 验证 ST (CAS 3.0)
└── GET  /cas/logout                  # 单点登出
```

#### 服务端 (Spring Boot Application)

本项目采用 **统一 SSO 架构**，通过 `SsoProvider` 策略接口抽象不同的 SSO 协议：

**核心组件**：
- `SsoProvider` - SSO 提供商策略接口，定义统一的认证流程
- `CasSsoProvider` - CAS 协议实现，处理票据验证
- `SsoController` - 统一 SSO API 控制器，暴露前端调用接口
- `SsoProviderRegistry` - 提供商注册中心，管理所有启用的 SSO 提供商

```java
// SsoProvider.java - 策略接口
public interface SsoProvider {
    String getProviderName();                    // 获取提供商名称（cas/keycloak）
    boolean isEnabled();                         // 检查是否启用
    String getLoginUrl(String redirectUri, String state);  // 获取登录 URL
    SsoAuthenticationResult handleCallback(HttpServletRequest request);  // 处理回调
    String getLogoutUrl(String postLogoutRedirectUri);     // 获取登出 URL
}

// SsoController.java - 统一 API
@RestController
@RequestMapping("/api/auth/sso")
public class SsoController {

    // 获取登录 URL
    @GetMapping("/{provider}/login-url")
    public R<SsoLoginUrlResponse> getLoginUrl(@PathVariable String provider, ...);

    // 处理 SSO 回调（重定向流程）
    @GetMapping("/{provider}/callback")
    public void handleCallback(@PathVariable String provider, ...);

    // 获取所有已启用的 SSO 提供商
    @GetMapping("/providers")
    public R<List<SsoProviderInfoResponse>> getProviders();
}
```

#### 3.2.2 CasSsoProvider 实现

```java
// CasSsoProvider.java
@Slf4j
@Component
@ConditionalOnProperty(prefix = "sso.cas", name = "enabled", havingValue = "true")
public class CasSsoProvider extends AbstractSsoProvider {

    private static final String PROVIDER_NAME = "cas";
    private static final String CALLBACK_PATH = "/api/auth/sso/cas/callback";

    @Resource
    private SsoProperties ssoProperties;

    private CasProperties casProperties;
    private Cas30ServiceTicketValidator ticketValidator;

    @PostConstruct
    public void init() {
        this.casProperties = ssoProperties.getCas();
        this.ticketValidator = new Cas30ServiceTicketValidator(casProperties.getServerUrlPrefix());
    }

    @Override
    public String getProviderName() {
        return PROVIDER_NAME;
    }

    @Override
    public boolean isEnabled() {
        return casProperties.isEnabled();
    }

    @Override
    public String getLoginUrl(String redirectUri, String state) {
        // 构建 CAS 服务 URL（回调地址）
        String serviceUrl = buildServiceUrl(redirectUri, state);
        // 返回完整的 CAS 登录 URL
        return casProperties.getServerLoginUrl() + "?service=" + urlEncode(serviceUrl);
    }

    @Override
    public SsoAuthenticationResult handleCallback(HttpServletRequest request)
            throws SsoAuthenticationException {
        String ticket = request.getParameter("ticket");
        if (!StringUtils.hasText(ticket)) {
            throw new SsoAuthenticationException(PROVIDER_NAME, "MISSING_TICKET", "缺少CAS ticket参数");
        }

        String redirectUri = request.getParameter("redirectUri");
        String state = request.getParameter("state");
        String serviceUrl = buildServiceUrl(redirectUri, state);

        try {
            // 验证票据
            Assertion assertion = ticketValidator.validate(ticket, serviceUrl);
            String username = assertion.getPrincipal().getName();
            Map<String, Object> attributes = assertion.getPrincipal().getAttributes();
            String email = getAttributeValue(attributes, "email", "mail");

            log.info("CAS认证成功: username={}", username);
            // 调用父类方法：同步用户 + 生成 Token
            return createAuthResult(username, username, email);

        } catch (TicketValidationException e) {
            throw new SsoAuthenticationException(PROVIDER_NAME, "TICKET_VALIDATION_FAILED",
                    "CAS ticket验证失败: " + e.getMessage(), e);
        }
    }

    @Override
    public String getLogoutUrl(String postLogoutRedirectUri) {
        String logoutUrl = casProperties.getServerUrlPrefix() + "/logout";
        if (StringUtils.hasText(postLogoutRedirectUri)) {
            logoutUrl += "?service=" + urlEncode(postLogoutRedirectUri);
        }
        return logoutUrl;
    }

    @Override
    protected String getDefaultRole() {
        return casProperties.getDefaultRole();
    }

    /**
     * 构建服务URL（CAS回调URL）
     */
    private String buildServiceUrl(String redirectUri, String state) {
        StringBuilder serviceUrl = new StringBuilder();
        serviceUrl.append(casProperties.getClientHostUrl());
        serviceUrl.append(CALLBACK_PATH);

        boolean hasParam = false;
        if (StringUtils.hasText(redirectUri)) {
            serviceUrl.append("?redirectUri=").append(urlEncode(redirectUri));
            hasParam = true;
        }
        if (StringUtils.hasText(state)) {
            serviceUrl.append(hasParam ? "&" : "?");
            serviceUrl.append("state=").append(urlEncode(state));
        }

        return serviceUrl.toString();
    }
}
```

```java
// SsoController.java
@Slf4j
@RestController
@RequestMapping("/api/auth/sso")
public class SsoController {

    @Resource
    private SsoProviderRegistry providerRegistry;

    @Resource
    private ITokenService tokenService;

    /**
     * 获取指定提供商的登录URL
     * GET /api/auth/sso/{provider}/login-url
     */
    @GetMapping("/{provider}/login-url")
    public R<SsoLoginUrlResponse> getLoginUrl(
            @PathVariable String provider,
            @RequestParam(required = false) String redirectUri,
            @RequestParam(required = false) String state) {

        SsoProvider ssoProvider = providerRegistry.getProviderOrThrow(provider);

        String actualState = StringUtils.hasText(state) ? state : UUID.randomUUID().toString();
        String loginUrl = ssoProvider.getLoginUrl(redirectUri, actualState);

        return R.ok(SsoLoginUrlResponse.builder()
                .provider(provider)
                .loginUrl(loginUrl)
                .state(actualState)
                .build());
    }

    /**
     * SSO回调处理（重定向流程）
     * GET /api/auth/sso/{provider}/callback
     */
    @GetMapping("/{provider}/callback")
    public void handleCallback(
            @PathVariable String provider,
            @RequestParam(required = false) String redirectUri,
            HttpServletRequest request,
            HttpServletResponse response) throws IOException {

        try {
            SsoProvider ssoProvider = providerRegistry.getProviderOrThrow(provider);
            SsoAuthenticationResult result = ssoProvider.handleCallback(request);

            // 设置Token Cookie
            setTokenCookie(response, result.getAccessToken());

            // 重定向到前端页面（带token参数）
            String targetUrl = buildRedirectUrl(redirectUri, result);
            response.sendRedirect(targetUrl);

        } catch (SsoAuthenticationException e) {
            log.error("SSO认证失败: {}", e.getMessage());
            redirectWithError(response, redirectUri, e.getErrorCode(), e.getMessage());
        }
    }

    private String buildRedirectUrl(String redirectUri, SsoAuthenticationResult result) {
        if (!StringUtils.hasText(redirectUri)) {
            redirectUri = "/";
        }
        String separator = redirectUri.contains("?") ? "&" : "?";
        return redirectUri + separator + "token=" + result.getAccessToken();
    }
}
```

## 四、OIDC/Keycloak 认证流程深度解析

### 4.1 三端交互视角（前端驱动模式）

#### 客户端 (Browser/Frontend)

```
1. 用户访问: http://localhost:3000/dashboard
   ↓
2. 前端检测未登录，显示登录页，点击"Keycloak 登录"按钮
   ↓
3. 前端调用 API: GET /api/auth/sso/keycloak/login-url?redirectUri=http://localhost:3000/dashboard
   ↓
4. 后端返回: { loginUrl: "http://keycloak/realms/.../auth?client_id=...", state: "xxx" }
   ↓
5. 前端跳转到 loginUrl
   ↓
6. 用户在 Keycloak 登录/授权
   ↓
7. Keycloak 重定向回:
   http://localhost:8888/api/auth/sso/keycloak/callback?code=abc456&state=xyz
   ↓
8. 后端用 code 交换 token，获取用户信息，生成本地 token
   ↓
9. 重定向到前端: http://localhost:3000/dashboard?token=xxx
   ↓
10. 前端路由守卫检测 URL 中的 token，保存到 localStorage/Cookie
```

#### 4.2.2 Cookie 授权请求存储

由于是无状态设计，需要将 OAuth2 授权请求保存到 Cookie：

```java
// HttpCookieOAuth2AuthorizationRequestRepository.java
@Component
public class HttpCookieOAuth2AuthorizationRequestRepository
        implements AuthorizationRequestRepository<OAuth2AuthorizationRequest> {

    private static final String COOKIE_NAME = "oauth2_auth_request";
    private static final int COOKIE_EXPIRE_SECONDS = 180;

    @Override
    public OAuth2AuthorizationRequest loadAuthorizationRequest(HttpServletRequest request) {
        return getCookie(request, COOKIE_NAME)
                .map(cookie -> deserialize(cookie, OAuth2AuthorizationRequest.class))
                .orElse(null);
    }

    @Override
    public void saveAuthorizationRequest(OAuth2AuthorizationRequest authorizationRequest,
                                         HttpServletRequest request,
                                         HttpServletResponse response) {
        if (authorizationRequest == null) {
            deleteCookie(request, response, COOKIE_NAME);
            return;
        }

        // 序列化授权请求到 Cookie
        addCookie(response, COOKIE_NAME,
                  serialize(authorizationRequest),
                  COOKIE_EXPIRE_SECONDS);
    }

    @Override
    public OAuth2AuthorizationRequest removeAuthorizationRequest(HttpServletRequest request) {
        return loadAuthorizationRequest(request);
    }

    // Base64 序列化
    private String serialize(Object object) {
        return Base64.getUrlEncoder().encodeToString(
            SerializationUtils.serialize(object)
        );
    }

    private <T> T deserialize(Cookie cookie, Class<T> cls) {
        return cls.cast(SerializationUtils.deserialize(
            Base64.getUrlDecoder().decode(cookie.getValue())
        ));
    }
}
```

#### 4.2.3 OIDC 认证成功处理

```java
// OidcAuthSuccessHandler.java
@Component
public class OidcAuthSuccessHandler extends SimpleUrlAuthenticationSuccessHandler {

    private static final String PROVIDER_NAME = "keycloak";

    @Override
    public void onAuthenticationSuccess(HttpServletRequest request,
                                       HttpServletResponse response,
                                       Authentication authentication)
            throws IOException, ServletException {
        log.info("OIDC 登录成功");

        // 1. 从认证信息中获取 OIDC 用户
        OidcUser oidcUser = (OidcUser) authentication.getPrincipal();

        // 2. 提取用户信息
        String sub = oidcUser.getSubject();  // 用户唯一标识
        String username = oidcUser.getPreferredUsername();
        String email = oidcUser.getEmail();

        // 兜底处理：如果 preferred_username 为空，使用 sub
        if (username == null || username.isEmpty()) {
            username = sub;
        }

        // 3. 同步用户到本地数据库
        String defaultRole = ssoProperties.getKeycloak().getDefaultRole();
        CustomUserDetails userDetails = ssoUserSyncService.syncUser(
            PROVIDER_NAME,
            sub,           // externalId (OIDC 用 sub)
            username,
            email,
            defaultRole
        );

        // 4. 生成 Token 并存入 Redis
        String token = tokenService.saveAccessToken(userDetails);

        // 5. 设置 Cookie
        Cookie cookie = new Cookie("am_access_token", token);
        cookie.setPath("/");
        cookie.setHttpOnly(false);
        cookie.setMaxAge(tokenTimeout.intValue());
        response.addCookie(cookie);

        // 6. 设置响应头
        response.setHeader("am_access_token", token);

        // 7. 重定向到前端
        response.sendRedirect(frontendUrl + "/dashboard");
    }
}
```

## 五、统一 Token 认证机制

### 5.1 Token 验证过滤器

无论用户通过哪种方式登录，后续请求都通过同一个 Filter 验证：

```java
// TokenAuthenticationFilter.java
@Component
public class TokenAuthenticationFilter extends OncePerRequestFilter {

    private static final String TOKEN_HEADER = "am_access_token";

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                    HttpServletResponse response,
                                    FilterChain filterChain)
            throws ServletException, IOException {
        try {
            // 1. 按优先级获取 Token
            String token = getTokenFromRequest(request);

            // 2. 验证 Token 有效性
            if (StringUtils.hasText(token) && tokenService.validateToken(token)) {

                // 3. 从 Redis 获取用户信息
                CustomUserDetails userDetails = tokenService.getUserByToken(token);

                if (userDetails != null) {
                    // 4. 构建认证对象
                    AuthenticationToken authentication =
                        new AuthenticationToken(userDetails, token);

                    // 5. 设置到 SecurityContext
                    SecurityContext context = SecurityContextHolder.createEmptyContext();
                    context.setAuthentication(authentication);
                    SecurityContextHolder.setContext(context);
                }
            }
        } catch (Exception e) {
            log.error("认证失败", e);
            SecurityContextHolder.clearContext();
        }

        filterChain.doFilter(request, response);
    }

    /**
     * Token 获取优先级：
     * 1. am_access_token Header
     * 2. Authorization: Bearer Header
     * 3. am_access_token Cookie
     */
    private String getTokenFromRequest(HttpServletRequest request) {
        // 1. Header
        String token = request.getHeader(TOKEN_HEADER);

        // 2. Bearer Token
        if (!StringUtils.hasText(token)) {
            String bearerToken = request.getHeader("Authorization");
            if (StringUtils.hasText(bearerToken) && bearerToken.startsWith("Bearer ")) {
                token = bearerToken.substring(7);
            }
        }

        // 3. Cookie
        if (!StringUtils.hasText(token)) {
            Cookie[] cookies = request.getCookies();
            if (cookies != null) {
                for (Cookie cookie : cookies) {
                    if (TOKEN_HEADER.equals(cookie.getName())) {
                        token = cookie.getValue();
                        break;
                    }
                }
            }
        }

        return token;
    }
}
```

### 5.2 Token 服务实现

```java
// TokenServiceImpl.java
@Service
public class TokenServiceImpl implements ITokenService {

    private static final String TOKEN_PREFIX = "auth:token:access:";

    @Resource
    private RedisTemplate<String, Object> redisTemplate;

    @Value("${auth.token-timeout:3600}")
    private Long tokenTimeout;

    /**
     * 生成并保存 Token
     */
    @Override
    public String saveAccessToken(CustomUserDetails userDetails) {
        // 生成随机 Token (非 JWT)
        String accessToken = UUID.randomUUID().toString().replace("-", "");

        String key = TOKEN_PREFIX + accessToken;

        // 保存到 Redis，设置过期时间
        redisTemplate.opsForValue().set(key, userDetails, tokenTimeout, TimeUnit.SECONDS);

        return accessToken;
    }

    /**
     * 根据 Token 获取用户信息
     * 关键：实时查询权限，处理权限变更
     */
    @Override
    public CustomUserDetails getUserByToken(String token) {
        String key = TOKEN_PREFIX + token;
        Object value = redisTemplate.opsForValue().get(key);

        if (value == null) {
            return null;
        }

        // 处理反序列化（Redis 返回可能是 LinkedHashMap）
        Long userId;
        if (value instanceof LinkedHashMap) {
            userId = Long.valueOf(((Integer)((LinkedHashMap<?, ?>) value).get("id")).toString());
        } else if (value instanceof CustomUserDetails) {
            userId = ((CustomUserDetails) value).getId();
        } else {
            return null;
        }

        // 实时查询用户和权限（支持动态权限变更）
        SysUser user = userService.getUserById(userId);
        Set<String> permissions = userService.getPermissionsByUserId(user.getId());

        return new CustomUserDetails(
            user.getId(),
            user.getUsername(),
            user.getPassword(),
            AuthorityUtils.createAuthorityList(permissions.toArray(new String[0]))
        );
    }

    @Override
    public void removeAccessToken(String token) {
        redisTemplate.delete(TOKEN_PREFIX + token);
    }

    @Override
    public boolean validateToken(String token) {
        return Boolean.TRUE.equals(redisTemplate.hasKey(TOKEN_PREFIX + token));
    }
}
```

### 5.3 SSO 用户同步服务

统一处理来自不同 SSO Provider 的用户：

```java
// SsoUserSyncServiceImpl.java
@Service
@Slf4j
public class SsoUserSyncServiceImpl implements SsoUserSyncService {

    @Override
    public CustomUserDetails syncUser(String provider, String externalId,
                                     String username, String email,
                                     String defaultRole) {
        log.info("同步 SSO 用户: provider={}, username={}", provider, username);

        // 1. 查询本地用户
        SysUser user = userService.findByUsername(username);

        if (user == null) {
            // 2. 创建新用户
            log.info("创建新 SSO 用户: {}", username);
            user = new SysUser();
            user.setUsername(username);
            user.setEmail(email);
            user.setPassword("");  // SSO 用户无本地密码
            user.setRole(defaultRole);
            user.setStatus(1);
            user.setCreatedAt(LocalDateTime.now());
            user.setUpdatedAt(LocalDateTime.now());
            user.setLastLoginTime(LocalDateTime.now());
            user = userService.saveUser(user);

            // 可选：为新用户分配默认角色
            roleService.assignDefaultRole(user.getId(), defaultRole);

        } else {
            // 3. 更新现有用户
            log.info("更新 SSO 用户登录时间: {}", username);

            // 更新邮箱（如有变化）
            if (email != null && !email.equals(user.getEmail())) {
                user.setEmail(email);
                user.setUpdatedAt(LocalDateTime.now());
            }
            userService.updateLastLoginTime(user.getId());
        }

        // 4. 获取用户权限
        Set<String> permissions = userService.getPermissionsByUserId(user.getId());

        // 5. 构建 CustomUserDetails
        return new CustomUserDetails(
            user.getId(),
            user.getUsername(),
            user.getPassword() != null ? user.getPassword() : "",
            permissions.stream()
                    .map(SimpleGrantedAuthority::new)
                    .collect(Collectors.toList())
        );
    }
}
```

## 六、完整流程对比

### 6.1 流程对比表

| 阶段 | CAS | OIDC/Keycloak |
|------|-----|---------------|
| **触发登录** | `GET /login/cas` | `GET /oauth2/authorization/keycloak` |
| **重定向到认证端** | `cas/login?service={url}` | `keycloak/auth?client_id=...&redirect_uri=...` |
| **认证凭证** | 票据 (ST-xxx) | 授权码 (code) |
| **凭证验证** | `CasAuthenticationProvider` → CAS Server | 后端用 code 交换 token |
| **用户信息获取** | `CasAuthenticationToken.getAssertion()` | JWT 解码 + UserInfo API |
| **回调地址** | `/login/cas?ticket=xxx` | `/api/auth/keycloak?code=xxx` |
| **核心组件** | 原生 `CasAuthenticationFilter` | 原生 `OAuth2LoginAuthenticationFilter` |
| **单点登出** | Back-Channel (CAS 推送) | Back-Channel (logout_token) |

### 6.2 安全性对比

| 安全特性 | CAS | OIDC |
|----------|-----|------|
| **票据/Token 类型** | 随机字符串 (ST) | JWT (可验证签名) |
| **防重放** | ST 一次性使用 | state + nonce |
| **签名验证** | 无 (信任 CAS Server) | RSA/ES256 签名 |
| **传输安全** | 必须 HTTPS | 必须 HTTPS |
| **客户端认证** | 无 | client_secret |

### 6.3 选型建议

**选择 CAS 的场景：**
- 企业内部系统，统一使用 CAS
- 已有 CAS 基础设施
- 对协议简单性有要求
- 不需要移动端支持

**选择 OIDC/Keycloak 的场景：**
- 新建项目，追求标准化
- 需要移动端 App 支持
- 需要社交登录集成
- 需要细粒度的权限控制 (Keycloak)
- 微服务架构

### 8.1 CAS 票据验证失败

**问题**：CAS 返回 `INVALID_TICKET` 错误

**原因**：
1. Service URL 不匹配
2. 票据已过期或已使用
3. CAS Server 未注册该 Service

**解决方案**：
```java
// 确保 service URL 完全一致
public String getServiceUrl() {
    // 不要有多余的斜杠或参数
    return clientHostUrl + loginPath;
}
```

### 8.2 OIDC state 不匹配

**问题**：Spring Security 报错 `OAuth2AuthenticationException: invalid state`

**原因**：Cookie 中的授权请求丢失或过期

**解决方案**：
```java
// 增加 Cookie 过期时间
private static final int COOKIE_EXPIRE_SECONDS = 300;  // 5 分钟

// 确保 SameSite 属性正确
cookie.setAttribute("SameSite", "Lax");
```

### 8.3 跨域问题

**问题**：前后端分离时出现 CORS 错误

```java
@Bean
public CorsConfigurationSource corsConfigurationSource() {
```

## 九、总结

本文基于一个实际的 Spring Boot 项目，深入分析了 CAS 和 OIDC 两种主流单点登录方案：

### 核心要点

1. **统一 SSO 架构**：通过 `SsoProvider` 策略接口抽象不同协议，实现统一的认证流程
2. **前端驱动模式**：前端不直接暴露 SSO 端点，通过 API 获取登录 URL
3. **统一回调路径**：所有 SSO 提供商使用 `/api/auth/sso/{provider}/callback`
4. **CAS** 适合企业内网环境，协议简单，基于票据验证
5. **OIDC** 是现代标准，基于 JWT，适合互联网和移动端
6. **统一 Token 机制** 使得不同登录方式可以共用后续的认证逻辑
7. **无状态设计** 通过 Redis 存储 Token，支持分布式部署

### 统一 SSO 架构的优势

| 特性 | 传统方式 | 统一架构 |
|------|---------|---------|
| **前端实现** | 每种 SSO 需要不同跳转逻辑 | 统一调用 `getSsoLoginUrl(provider)` |
| **回调路径** | CAS: `/login/cas`<br>OIDC: `/api/auth/keycloak` | 统一：`/api/auth/sso/{provider}/callback` |
| **安全性** | 暴露具体 SSO 端点 | 登录 URL 由后端生成 |
| **扩展性** | 添加新 SSO 需修改多处 | 实现 SsoProvider 接口即可 |
| **维护成本** | 多套代码逻辑 | 统一 SsoController |
